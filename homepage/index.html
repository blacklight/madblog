Your blog is a folder of Markdown files

Madblog is a self-hosted blogging platform and Web framework that runs straight from a directory of .md files. No database, no lock-in — and the open Web's protocols wired in by default.

Markdown, not a CMS

Your content is text. Text is forever.

Point Madblog at a folder of Markdown files — an Obsidian vault, a Nextcloud Notes folder, a git clone, a directory synced over SyncThing — and it becomes a blog. There is no database to back up, no export to request, no format to migrate away from.

  • No database required — just a folder with your Markdown files. Editing a post is as simple as editing a file on your server
  • YAML front matter for titles, descriptions, dates, authors and tags — metadata lives in the file, not in a CMS database
  • Folders are categories — nested directories become navigable sections, each with its own index page and feeds
  • View modes for every taste — card grid, compact list or a full WordPress-style scrolling view
Federation & the open web

Your blog joins the conversation

This isn't a static site generator that merely looks indie. Madblog speaks the protocols that make the web social — so comments land on your site, not on someone else's platform.

  • ActivityPub federation — your blog gets an actor like @blog@example.com. Mastodon users can follow it, reply to it and boost it
  • Mastodon-compatible API — a sensible implementation of the Mastodon client API comes built in
  • Webmentions in both directions — get notified when blogs link your posts, and ping the sources you link to
  • Author replies & reactions — respond to mentions as plain Markdown files under replies/, threaded inline on the post
Rendering & syndication

Serious output from plain text

Madblog renders your Markdown on the server — no JavaScript framework, no build step. Technical posts, diagrams and feeds all come out of the same file.

  • LaTeX equations rendered to images with caching — inline and display math just work
  • Mermaid diagrams compiled to inline SVG via mermaid-cli or npx
  • RSS 2.0 & Atom feeds for the blog, every folder, tag and the guestbook
  • Rich link previews via OpenGraph, plus a PWA manifest for installable blogs
And there's more

A small codebase with surprising depth

Everything below is a config flag away — the unglamorous pieces are already where they should be.

📖

Guestbook mode

A dedicated page aggregates public mentions from Webmentions and ActivityPub into a single guest registry for your site.

📡

Aggregator mode

Render external RSS or Atom feeds directly in your blog — great for affiliated blogs or a self-hosted news reader.

🛡️

Flexible moderation

Blocklist or allowlist mode with rules on domains, usernames and URLs — regular expressions supported.

👁️

Visibility controls

Per-post visibility — public, unlisted or replies-only — so you decide what federates and what stays home.

🏷️

Tags & categories

Hashtags in front matter or inline in the body build a tag index; filesystem folders give you hierarchical sections.

✉️

Email notifications

Optional SMTP notifications when new Webmentions or ActivityPub interactions arrive on your posts.

📱

Installable PWA

A web app manifest and service worker turn any Madblog site into an installable app with offline support.

⚙️

Env-var configuration

Every option in config.yaml is also a MADBLOG_* environment variable — twelve-factor friendly.
